## 0.8.1 — 2026-11-23

### Config page: collapsible sections
The page used to be one flat list of eight sliders. It now uses BaseLib's own section mechanism, so
it reads like BaseLib's page:

- **Floors per act** (expanded) — the three floor sliders.
- **Treasure rows** (folded) — the "one row of treasure rooms every N rows" slider.
- **Room mix** (folded) — unknown / shop / rest / elite percentages.

Section titles are translated with the rest of the config page (English and Chinese).

### Treasure map act: one chest per chest row
In the act generated by the treasure map card, the special chest sits in the middle of its row and
every other room of that row is rerouted through it. The bonus treasure rows now leave that row
alone, and any stray chest that ends up there is turned back into a normal fight, so the special
chest is the only chest of its row. The other bonus treasure rows of that act are unchanged.

### Docs
`README.md` now only describes the mod and the current release; the full history lives here. Both
README and changelog exist in English and Chinese.

## 0.8.0 — 2026-11-23

### New: up to +50 floors per act
The three floor sliders now go to 50 (`FloorSettings.MaxFloors = 50`); `Act1ExtraFloors`,
`Act2ExtraFloors` and `Act3ExtraFloors` in `settings.cfg` accept 0–50 and are clamped on load.

### New: configurable room shares
Four new sliders set the share of unknown rooms, shops, rest sites and elites (0–100, step 5). The
remainder becomes a normal fight, so the five values always add up to 100.

- `0 / 0 / 0 / 0` keeps the vanilla mix and is the default, so existing configs behave exactly as before.
- Values that add up to more than 100 are scaled down proportionally.
- Only **changeable** rooms of acts that actually gained floors are re-rolled: the first row stays
  normal fights, and the treasure row, the starting rooms and the boss row are untouched.
- The vanilla pacing rules still apply: no elite above row 6, no rest site below row 5 or in the
  last three rows, no two rooms of the same special type next to each other, at most one
  shop/elite/rest per row.
- At least one shop and one rest site are kept when their share is above zero; elites are capped at 14.
- Randomness comes from a stream derived from the map's own RNG (`Rng` has no public seed, so it is
  cloned through `mapRng.ToSerializable()`), so both co-op peers roll the same map.
- In co-op the host's four shares travel with the three floor values in `HostFloorsMessage`
  (the message grew from 3 to 7 bytes).

### Tests
Offline cases went from 112 to 128 (covering 0–50 floors). New `RoomMixHarness`: normalisation,
peer determinism, vanilla pacing rules, untouched vanilla-length acts.

### Config file
`settings.cfg` gained `UnknownPercent`, `ShopPercent`, `RestPercent`, `ElitePercent` (0–100).

## 0.7.2 — 2026-11-23

### Fixed: the treasure-map act froze the game
The treasure map event replaces act 2 with the hourglass-shaped `SpoilsActMap`, which calls
`MapPathPruning.PruneAndRepair` and enumerates **every possible route** of the map. Harmless at 16
rows, astronomically large at 45 — the CPU filled up, memory grew past 4 GB and the game stopped
responding (`actMap ms=1` followed by nothing, plus an `Application Hang` entry in Windows).

- New `LongMapPruningPatch`: maps longer than 20 rows skip that pass entirely.
- New `LongMapRule.Scaled` in `MapCompat.cs`: with the pruning skipped, the unknown/shop/rest/elite
  budget is scaled by `rooms/(rooms-extra)`, elites capped at 14.
- Side effect: very long maps no longer prune duplicate-looking segments, so two paths may look
  identical (connectivity and boss reachability are unaffected).

### Fixed: the treasure-map act ignored the extra floors
`SpoilsActMap` takes its length from `act.GetNumberOfRooms(isMultiplayer) + 1`, and that call is
inlined in the constructor, so the harmony postfix never saw it and the act stayed at 14 rows.

- A transpiler on the `SpoilsActMap` constructor rewrites the call to
  `RoomCountPatch.EffectiveRooms`, so the act now grows with the setting (45 rows at +30).

### Fixed: the golden compass ignored the extra floors
`GoldenPathActMap` is a hard-coded 16-room straight line.

- New `GoldenPathPatch`: a transpiler inserts `GoldenPathPatch.Types` after `ToList()` and stretches
  the 16-room template to the configured length — monster first, rest site last, treasure ×2,
  shop ×1, elite ×2, rest site ×4 distributed proportionally, everything else monster/unknown; the
  multiplayer "drop one room at the start" behaviour is kept.

### Added: a row of treasure rooms every N rows
- New `TreasureEveryRows` setting (0–30, default **7**), for stretched maps only: the vanilla
  treasure row counts as the first of the series and every N rows above it becomes a treasure row.
  `0` disables it.
- Editable on the config page, in `settings.cfg`, or by editing the file before starting the game.
- Vanilla-length acts keep the vanilla chest count.

### Improved: how the parchment background is stretched
Scaling the whole sheet vertically blew up the two rolled ends and left the middle narrower than
the rolls (the texture is 2036×1440 and vanilla keeps the aspect inside a 1920×1080 box, so the
paper is drawn 1527×1080).

- The two rolled ends are now **completely untouched**; the middle keeps the vanilla width and is
  stacked as strips (each about 6% taller than vanilla), so the sheet grows upward between the rolls.
- The bottom edge stays pinned, which also removed the overhang at the bottom of act 2.
- Width, side margins and paper texture now match vanilla exactly.

### Other
- Diagnostics are **opt-in**: the log only exists while `%APPDATA%\SlayTheSpire2\ActFloorCustomizer-test.txt`
  is present. A normal install writes no log file.
- New `CHANGELOG.md` (this file).

### Known issue: other map mods can drop the frame rate
- The **minimap overview** of the "Map Enhance" mod rebuilds a large map preview: on a 46-row act
  the map screen dropped to about 6 FPS (memory swinging between 0.5 and 3.2 GB). Turning the
  minimap overview off, or disabling that mod, restores the frame rate. Its **route analysis** is
  worse — keep each act at 15 floors or below while it is enabled.
- This mod's own drawing cost grows linearly with the row count; lowering the floor setting is the
  reliable fix when another mod slows down.

## 0.7.0 — 2026-11-22

- Co-op now follows **the host's settings**: the host sends its three values when the run starts and
  the clients ignore their own sliders, so the maps cannot desync.
- New custom network message `HostFloorsMessage` (reliable, ordered) plus the send/receive/cache
  logic in `HostSync`.
- Changing a value during a run only affects the next run's maps.
